## Top 3 lessons

1. **Open findings, status check: all still open.** Because nothing but reflections has landed since
   e737d2e, every finding from the last two files stands unchanged on `main`:
   - `$SHONOKIN_ROOT` typo in [`README.md`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/README.md)
     and [`MISSION.md`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/skills/shokunin/protocol/MISSION.md)
     vs. `SHOKUNIN_ROOT` everywhere else (first seen 10-20).
   - No seed or schema for `SCORECARD.md` even though six protocol files route claims through it (first seen 10-21).
   - The watchdog's `sources_gate` fails open when the census script is missing or returns an unexpected
     code (first seen 10-20).
   - e737d2e is authored `ci <ci@shokunin.local>` with no recorded non-author review (first seen 10-20).
   Four open findings on a repo whose protocol prizes "verified" work is the main thing worth João's
   attention; the typo and the SCORECARD seed are both small, low-risk fixes.

2. **The census selftest only runs when someone installs.** e737d2e added
   [`scripts/sources-census.sh`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/scripts/sources-census.sh)
   (806 lines) with a `selftest` mode and nine fixture files under
   [`scripts/fixtures/sources-census/`](https://github.com/VeigaPunk/kimi-shokunin/tree/main/scripts/fixtures/sources-census),
   including an injection fixture, and [`install.sh`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/install.sh)
   gates on it. But the repo has no `.github/` directory, so no CI runs the selftest on push. A protocol
   edit to `CORPUS.md` that changes the SOURCES contract could drift from the validator (E01–E12, W01–W04)
   and nobody would find out until the next install. The test exists; what's missing is a trigger.

3. **The watchdog swallows its own conformance signal.** In
   [`scripts/shokunin-watchdog.sh`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/scripts/shokunin-watchdog.sh),
   `report_sources_conformance "$lane" "$n" || true` means a conformance failure is logged but never
   changes the round's outcome. Together with the fail-open `sources_gate` (finding 1), the SOURCES
   contract is currently advisory at runtime, enforced only at install time and by the lane's own
   honesty. That may be deliberate (don't kill a round over a log line), but the protocol docs describe it
   as a contract, so the docs and the driver should agree on which it is.
