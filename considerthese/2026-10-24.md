## Top 3 lessons

1. **The axes contract and the lane roster don't speak the same vocabulary.** `AXES.md` defines six
   named axes (depth, coverage, operability, freshness, calibration, adjacency) and requires each
   round to work the lane's "lowest-scoring non-retired axis". But
   [`templates/shokunin.conf.example`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/templates/shokunin.conf.example)
   seeds lanes with free-text phrases like `fleet-meta: protocol soundness, gate integrity`, and
   [`scripts/shokunin-watchdog.sh`](https://github.com/VeigaPunk/kimi-shokunin/blob/main/scripts/shokunin-watchdog.sh)
   (lines 71–80) just trims the field and substitutes it into `{{AXES}}`. Nothing guarantees a
   lane's axes are ones the scoring rule can rank, so "lowest-scoring axis" can be undefined for the
   very lanes that ship in the example.
2. **"Fleet-level axes" is a dangling reference.** `AXES.md` line 4 assigns them to the protocol and
   aggregator lanes, yet the file lists only the six per-skill axes. Together with the missing
   `SCORECARD.md` seed, the two meta-lanes currently have no measurable contract at all.
3. **Quiet days are worth more as audits than as change logs.** Five days with no substantive commit
   produced two new findings only because a protocol file was read end to end against its
   consumers. The rotation should continue (next: `CORPUS.md`).
